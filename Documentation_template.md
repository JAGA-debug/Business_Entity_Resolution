# Business Entity Resolution Methodology

## 1. Executive Summary
This project resolves Source 1 reference businesses against records in Sources 2 and 3. The submitted outputs were generated by a LightGBM binary classifier trained on labeled and sampled candidate pairs, preceded by country-aware blocking and text/address similarity features. The test data is processed dynamically by country label, including France, which is absent from the training data.

## 2. Methodology & Architecture
The submitted outputs are produced by `code/business_entity_resolution/src/train_and_predict.py`:
1. **Training data preparation:** The script reads up to 40,000 ground-truth rows, builds normalized source records, and generates positive pairs plus up to three blocked negative pairs per reference.
2. **Candidate generation and scoring:** A multi-key inverted index proposes up to 25 test candidates per reference. A LightGBM binary classifier scores the resulting feature vectors.
3. **Conflict handling and output:** Each candidate target is assigned to the reference with its highest score. Per-reference confidence thresholds are then applied, and both output TSV files are written in Source 1 order.

## 3. Candidate Generation / Blocking Strategy
- **Country Partitioning:** Test references and targets are grouped by their country string at inference time; labels are not restricted to the training countries, so France is handled without a country-specific model.
- **Inverted Index Channels:**
  - First-token and first-two-token keys from normalized names after removing common legal terms for blocking.
  - Keys combining the first name token with address digit strings, plus digit-only keys for strings of at least three digits.
  - Posting lists are capped at 50 IDs per key; the query returns at most 25 candidates per test reference (20 during training-pair generation).
- The candidate file records the test blocker results that are passed to the scoring model, before final matching thresholds are applied.

## 4. Feature Engineering & Similarity Scoring
- **Text Normalization:** `anyascii` transliterates names and addresses; text is lowercased, ampersands become "and", and punctuation is normalized. Common legal terms are removed when creating name blocking keys, but remain in the classifier's normalized-text features.
- **Nine pair features:** RapidFuzz token-set, token-sort, and ratio scores for names; token-set and ratio scores for addresses; presence and count of shared address digit strings; and absolute character-length differences for name and address.
- **Classifier:** LightGBM binary GBDT with 300 boosting rounds, learning rate 0.08, 31 leaves, and binary log-loss validation. Training uses an 80/20 stratified split with `random_state=42`; the script does not print a validation F-score or use early stopping.

## 5. Metric Alignment & Threshold Tuning (Macro F0.5)
The challenge uses macro-averaged F0.5, which weights precision more heavily than recall. Candidate targets are first assigned to the Source 1 record with the highest predicted probability. For each reference, the highest-scoring owned candidate uses a threshold of **0.65**; subsequent candidates use **0.78**. This is per-target highest-score ownership, not a maximum-weight bipartite matching algorithm. The checked-in prediction files contain 1,732,544 rows each; `matching_results.tsv` has 1,391,816 non-empty rows. These are output counts, not an accuracy or leaderboard score.

## 6. Reproduction and Limitations
Install the pinned dependencies listed in `code/business_entity_resolution/requirements.txt`, then run the command in `code/business_entity_resolution/README.md` from the project root. The script expects the supplied `dataset/train/` and `dataset/test/` TSVs at that root and writes both outputs under `output/`. It trains a fresh classifier each run; there is no saved model artifact. The selected 40,000-row ground-truth limit and sampled negatives are implementation choices, not evidence of a measured validation score. No external identity lookup or pretrained model is used.
